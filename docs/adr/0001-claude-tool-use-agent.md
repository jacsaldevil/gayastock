# ADR-001: Claude tool_use 기반 에이전트 아키텍처 채택

- **상태**: Accepted
- **날짜**: 2026-05-01

## 배경

국내 주식 매매 에이전트를 구현할 때 두 가지 방향을 검토했다.

- **룰 기반**: 이동평균 크로스오버, RSI 등 사전 정의된 조건으로 매매 신호 생성
- **LLM 기반**: AI가 재무제표를 읽고 스스로 판단

재무제표 기반 가치투자는 정형화된 조건으로 표현하기 어렵다. PER이 낮아도 업종 특성상 적정한 경우가 있고, 부채비율도 금융업과 제조업의 기준이 다르다. 이런 맥락적 판단이 필요한 영역에서는 LLM이 룰 기반보다 적합하다고 판단했다.

## 결정

**Claude API의 tool_use 기능으로 에이전트를 구현한다.**

에이전트가 스스로 tool 호출 순서를 결정하는 루프 구조를 채택했다.

```
Claude → get_portfolio
       → get_stock_price(종목)
       → get_financial_statements(종목)
       → buy_stock / sell_stock / (보유)
       → 최종 요약 텍스트 반환
```

tool_use stop_reason이 나올 때마다 tool을 실행하고 결과를 messages에 추가하는 방식으로, Claude가 필요한 정보를 스스로 수집한 뒤 판단한다.

## 검토한 대안

| 방식 | 탈락 이유 |
|------|-----------|
| 룰 기반 (이동평균, RSI) | 재무제표 분석에 부적합, 맥락 판단 불가 |
| LangChain Agent | 의존성 무거움, tool_use 직접 구현이 더 단순 |
| OpenAI Function Calling | 이미 Claude 환경이므로 불필요 |

## 결과

- **긍정적**: 종목마다 다른 기준을 적용 가능, 판단 근거를 텍스트로 남길 수 있음
- **부정적**: API 비용 발생, 동일 입력에도 결과가 달라질 수 있음 (비결정적)
- **제약**: 매매 판단의 재현성이 낮으므로 백테스팅에는 부적합. 백테스팅은 별도 룰 기반으로 구현해야 함
