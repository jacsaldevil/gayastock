## 현재 전략 — v5 거래량 모멘텀 + LLM 자율 판단

### 핵심 개념

- **종목 선정**: 재무 필터 없음. 매 실행마다 거래량 Top30 스캔 → ETF/스팩 제외 후 상위 10종목
- **진입 판단**: VWAP + 60분치 3분봉 HA 캔들 추세를 LLM이 종합 자율 판단
- **청산**: 당일 11:30 전량 강제 청산 (오버나이트 리스크 제로)
- **Google Search**: 1회차(09:20)에만 시장 테마/이슈 파악

### v4 → v5 핵심 변경

| 항목 | v4 | v5 |
|---|---|---|
| 진입 기준 | VWAP 구간별 HA 기계적 게이트 | LLM 자율 판단 (코드 가드레일만 유지) |
| HA 캔들 | 3분봉 10개 (30분치) | 3분봉 20개 (60분치) |
| VWAP 0~+1% | 진입 금지 | LLM 자율 판단 |
| VWAP +3% 초과 | 진입 금지 (규칙) | LLM 자율 판단 (코드 차단 없음) |
| 손절 재진입 차단 | 프롬프트 텍스트 규칙 | **코드 레벨 강제** |
| 내부 루프 | 5회, 90초 슬립 | 3회, 30초 슬립 |
| 로그 보존 | 건수 기반 (최대 1,000건) | 최근 거래일 단위 자동 삭제 |

### 실행 구조

```
Cloud Scheduler (20회/일, 7분 간격, 09:20~11:30)
  → Cloud Run Job (main.py --once)
      → 세션 루프 3회 (루프 간 30초 슬립)
          ├─ [루프 1~3] Python 사전 체크 (get_balance + HA/VWAP)
          │   ├─ TP/SL 조건 or 빈 슬롯 or 보유 종목 VWAP 음수 → Gemini 호출
          │   └─ 조건 없으면 스킵
          └─ 3루프 완료 후 최종 요약 LLM 1회 호출 → 세션 로그 기록
```

**실질 모니터링 주기**: 스케줄 7분 × 내부 3회 = **약 3분 간격**

### 스케줄 (7분 간격, cron KST)

|---|---|---|
| 1 | 09:20 | 진입 — Google 검색 + Top10 스캔 |
| 2~8 | 09:27~10:09 | 오전 점검 |
| 9~15 | 10:16~10:58 | 오전 후반 — 진입 기준 스스로 높임 |
| 16~18 | 11:05~11:19 | 정리 — 신규 진입 원칙적 금지 |
| 20 | 11:30 | **강제 청산 — 전량 매도** |

### 진입 판단 — LLM 자율 판단

**get_heikin_ashi_candles** 호출 시 반환:
- 최근 1분봉 60개 → 3분봉 20개 HA 캔들 (60분치 추세)
- VWAP (당일 전체 1분봉 기준)
- VWAP 이탈률 = (현재가 - VWAP) / VWAP × 100

**하드 가드레일 (코드로 강제)**

| 조건 | 처리 |
|---|---|
| VWAP 음수 | buy_stock 호출 차단 (코드) |
| 당일 손절 종목 | buy_stock 호출 차단 (코드) — 세션 재기동 시 GCS trade_log에서 복원 |

**LLM 자율 판단 요소**

- HA 캔들 60분치 추세 (방향성, 모멘텀, 반전 신호)
- VWAP 이탈률 강도와 추격 위험
- 거래량 순위 (시장 주도 가능성)
- 시장 맥락 (1회차 Google 검색 결과)
- 시간대 (후반일수록 진입 기준 자율 상향)

### 포지션 사이징

```
매수금액 = 가용예수금 × 30~50% ÷ 남은 슬롯 수
  - 확신 높음: 50%
  - 불확실: 30% 이하
주문 수량 = 매수금액 ÷ 현재가 (소수점 버림)
최대 보유 종목: MAX_POSITIONS개
```

### 포지션 교체 (예수금 부족 시)

아래 3가지 조건 충족 시 보유 종목 중 약한 종목을 청산하고 신규 매수 허용:

1. 신규 종목 VWAP 이탈률 양수이고 +3% 미만
2. 가용예수금 < 필요금액의 50%
3. 현재 시각 10:58 이전

**청산 후보 우선순위**: VWAP 음수 종목 → 손실 종목 → VWAP 이탈률 낮은 종목

교체 후보가 없거나 모두 신규보다 VWAP 이탈률이 높으면 교체 안 함.

### 청산 조건

| 조건 | 기준 |
|---|---|
| 익절 (TP) | 수익률 +4% 이상 (즉시) |
| 손절 (SL) | 수익률 -2.5% 이하 (즉시) |
| HA/VWAP 이탈 | 캔들 추세·VWAP 흐름 LLM 자율 판단 |
| 강제 청산 | 11:30 전량 |

### Python 사전 체크 (LLM 호출 게이트)

```
포트폴리오 조회
├─ 보유 종목 TP/SL 조건 해당 → LLM 호출
├─ 빈 슬롯 있음 (보유 < MAX_POSITIONS) → LLM 호출
├─ 포지션 풀 + 보유 종목 중 VWAP < 0 → LLM 호출
└─ 위 조건 없음 → 스킵 (LLM 비용 절감)
```

### 코드 레벨 리스크 관리

| 규칙 | 구현 위치 |
|---|---|
| VWAP 음수 진입 차단 | `agent/tools.py` buy_stock 핸들러 |
| 당일 손절 종목 재진입 차단 | `agent/tools.py` `_stopped_out_today` 세트 — 세션 시작 시 GCS trade_log 로드 |
| 미체결 주문 자동 취소 | `broker/kis.py` `cancel_all_pending_orders()` — 세션 첫 루프에서 실행 |
| 미체결 취소 로그 | `data/trade_log.py` `log_cancel()` — CANCEL 액션으로 기록 |

### 파라미터 (config.py / deploy.yml)

```python
TAKE_PROFIT_PCT      = 4.0   # 익절 기준 (%)
STOP_LOSS_PCT        = 2.5   # 손절 기준 (%)
MAX_POSITIONS        = 5     # 최대 보유 종목
INNER_LOOP_COUNT     = 3     # 스케줄 1회당 내부 루프 수
INNER_LOOP_SLEEP_SEC = 30    # 루프 간 슬립 (초)
```
